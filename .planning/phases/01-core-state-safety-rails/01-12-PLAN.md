  <action>
src/core/proc/exec.ts: `execFileJson(cmd, args, {cwd, env, timeoutMs, input?})` spawns with node:child_process `spawn(cmd, args, {cwd, env, shell: false})`: an argv array, never a shell string (CLAUDE.md: never build a shell string from external content). It resolves, and never rejects on a non-zero exit, to `{code, stdout, stderr, json}`, where `json` is the parsed stdout or `undefined` when stdout is not JSON. A timeout sends SIGTERM, then SIGKILL after 2 s, and resolves with `code: 124` and `timedOut: true`; a spawn error such as ENOENT resolves with `code: 127`. Only `node:` built-ins are imported.

test/helpers/fake-bin.ts: `withFakeBin({claude?, gh?, security?}) → {env, calls()}`, synchronous, where each spec maps a space-joined argv key to `{stdout?, stderr?, code?}`. It writes the specs to a temp JSON (mkdtemp under os.tmpdir()) and returns a copy of process.env with test/helpers/fake-bin prepended to PATH and WARDEN_FAKE_BIN_SPEC and WARDEN_FAKE_BIN_LOG set. `calls()` reads the JSON-lines log as `{bin, argv, env}` entries; `env` holds only the RESEARCH Pattern 1 deny-list names plus CLAUDE_CONFIG_DIR and GH_TOKEN, so tests can assert which credentials a child saw. The three executables test/helpers/fake-bin/{claude,gh,security} are identical `#!/usr/bin/env node` replay scripts, committed with mode 0755. Each one appends its log line first, then looks up the spec for its own basename, writes stdout and stderr, and exits with the canned code. When no key is canned it writes `fake-bin: no canned response for <bin> <argv>` to stderr and exits 127. Write the scripts with dynamic `import()` only (no `require`, no static `import`, no top-level await), so they run whether Node treats an extensionless file as CommonJS or ESM: plan 01-01 adds `"type":"module"` to package.json in this same wave.
  </action>

test/helpers/fake-fetch.ts exports `createFakeGitHub(seed?)` returning `{fetch, store, calls()}`. `seed` may hold `issues` and `pulls` (number, user, labels), `repoLabels`, `comments`, `reviews`, `timeline` and `contents` (path → text). `fetch` takes `(url, init)` and returns a WHATWG `Response`, so it plugs into Octokit's `request.fetch`. It is backed by an in-memory store of repo labels and per-issue labels (names compared case-insensitively as on GitHub, RESEARCH Pitfall 6); issue comments with numeric ids, user {id,type,login}, performed_via_github_app, body, created_at, and updated_at at one-second resolution (RESEARCH Pitfall 3); reviews; timeline label events; and repository contents served base64-encoded for GET /repos/{o}/{r}/contents/{path}?ref=. Routes cover the REST paths COVERAGE.md marks INTEGRATE for labels, comments, reviews and contents, including DELETE /repos/{o}/{r}/issues/{n}/labels/{name} with a URL-encoded name. A label POST on an issue that is not in the store answers 404. PUT /repos/{o}/{r}/issues/{n}/labels answers 200 and is recorded like every other call, so tests can assert it never happens. `calls()` returns every request as {method, url, body}; unknown routes return 404 with a JSON message. Only `node:` built-ins and the global fetch types are used.

src/core/paths.ts: `dataDir(env = process.env)` returns env.CLAUDE_PLUGIN_DATA when set and non-empty, else `${env.CLAUDE_CONFIG_DIR || <os.homedir()>/.claude}/plugins/data/warden-artificer`. `ensureDataDir(env?)` creates it with mode 0700. Nothing resolves under CLAUDE_PLUGIN_ROOT (CLAUDE.md: that directory is deleted 14 days after an update).
