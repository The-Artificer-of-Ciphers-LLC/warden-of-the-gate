## Product and design

Warden is a local-first GitHub software factory: review/merge PRs, fix bugs, build approved features and enhancements, and learn from maintainer decisions. The MVP is one repository per instance, manually triggered local AI on a Mac with OpenCode, plus deterministic Actions housekeeping and a serialized effects writer.

Read [the glossary](../../GLOSSARY.md), [PRD](../prd/0001-warden-of-the-gate.md), [implementation plan](../prd/0001-warden-of-the-gate.implementation-plan.md), [credential ADR](../adr/0011-credential-controller.md) and [serialized-writer ADR](../adr/0012-serialized-actions-state-writer.md). The design includes twelve draft ADRs and a P0-P7 coverage trace.

The accepted offline workflow and shadow-review prototypes demonstrate interaction/logic only, not live integrations. The first useful functional demo is P3's single live **shadow** PR review, after P2 bookkeeping. No calendar date has been committed.

### Addendum 2: sweep wired to the writer (offline, still unscheduled)

Owner chose "Wire sweep to writer". Package: 91/91 tests, typecheck and build clean.

- New intent kind `sweep-action` (deterministic origin only). The reducer re-evaluates the clock against the **current ledger** and accepts only if the planned verdict still holds; the writer re-reads author comments and the `keep-open` label **at decision time** (`observeSweep`), so a reply or label added after planning defeats a stale closure. Intent payload carries only the expectation, never trusted facts.
- Enforced verdicts: 48h/72h nudge (once per silence start, tracked in the new optional `ledger.sweep`), five-day PR silence close, 14-day reproduction and 28-day other-information close. Closure = label projection + explanation comment (reason, retained linked issues, return path) + new `close` effect confirmed against GitHub before acknowledgement.
- `warden run --task sweep --dry-run` is read-only and proposes; **live sweep stays `unsupported`** (no Actions handler, no schedule). `submitSweep` exists for the handler to call.
- Known gaps, not hidden: delivery/fix-window **expiry and claim release are not enforced** (no unassign effect; ledger has no satisfaction/hold fields); push/review replies are not observable through `Store`, so only comments reset silence; designated-draft exemption is not wired; voice/signature config is not applied to messages; information obligations default to the 28-day window unless `source` contains "reproduction"; nothing creates `response`/`information` obligations yet (Intake/Claim, not built); items without a ledger are never swept (adoption not built).
- Not exercised against live GitHub or an Actions runner.

### Addendum 3: unassign and commitment expiry (offline, unscheduled)

Owner chose "Add unassign + expiry". Package: 97/97 tests, typecheck and build clean.

- New `Store.removeAssignee` (fake and HTTP; HTTP is not exercised live) and `unassign` effect, confirmed against GitHub before acknowledgement.
- `expire-commitment` is now enforced through `sweep-action`: an expired **delivery** commitment on an issue releases the claim (unassign, back to `ready`, label projected, issue stays open, linked partial-work refs named, expired obligation removed); an expired **fix-window** on a PR closes it with explanation while the original issue stays open. Releases are idempotent and a stale sweep (for example after the owner already released) is rejected by the reducer.
- Exemption split: confirmed/approved issues and unreviewed PRs are shielded from stale **closure** but not from a missed commitment; keep-open and maintainer waits shield both.
- Safety default: an issue with linked work or in `in-review` is treated as "completeness unassessed" and is deferred, never expired on a guess.
- Still open: nothing yet **sets** `satisfiedAt`, `hold` or creates delivery/fix-window obligations (Claim, maintainer hold/release intents, review-round tracking are unbuilt), so in practice only hand-seeded ledgers carry commitments. The "48-hour" text in the PR message is fixed rather than read from config. Contributor fix-round exhaustion routing, factory-owned claims and cross-item release of a linked issue when its PR closes are not implemented. Still simulated GitHub only.

### Addendum 4: Intake and Claim through the writer (offline, unscheduled)

Owner chose "Intake and Claim". Package: 106/106 tests, typecheck and build clean.

- **Intake (live, writer-side):** new `intake` intent (deterministic only). `submitIntake` takes **explicit item numbers only**, never scans the backlog, and skips items that already have a ledger, so intake cannot become blanket adoption. The writer re-derives the decision from the current GitHub item (`decideIntake`, shared with the dry-run) and a stale plan loses silently. Complete issue -> `needs-triage` (label only, no noise comment); empty body/short title -> `needs-info` with a request comment and a 28-day `information` obligation (source `metadata`, so the sweep closes it later); PR -> `needs-review`.
- **Claim:** existing claim intent now (1) rejects when GitHub already shows a different assignee (fresh ownership check at decision time), (2) starts the 48h `delivery` obligation for contributor claims at the **writer's decision time**, (3) release drops it. Factory claims carry no obligation. Competing claims leave one owner and one obligation. The full loop is tested: claim -> obligation -> sweep expiry -> unassign.
- **Not built, by design or yet:** claim authenticity still trusts the submitter-asserted actor (no `gh-comment` source verification for claims; the handler must vouch); no parser for "I'll take this" comments or Actions event handler; similarity candidates and template/explicit-route checks; draft-PR policy (a draft is only queued, never closed); the assignment timestamp is decision time, not GitHub's assignment event time; `fix-window` obligations are still not created (needs review-round tracking); maintainer hold/release and `satisfiedAt` writers; adoption (`warden adopt`); live CLI intake and live sweep remain `unsupported` (the CLI holds only the operator identity, not the submitter identity).
